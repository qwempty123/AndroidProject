# Анализ предметной области CourseMarket

## 1. Назначение

CourseMarket — мобильное приложение для просмотра каталога образовательных программ, оформления демонстрационного заказа и самостоятельного прохождения учебных материалов. Приложение рассчитано на локальную работу на одном Android-устройстве: данные учётных записей, каталог, корзина, заказы и учебный прогресс сохраняются в SQLite.

## 2. Цель проекта

Автоматизировать основные действия пользователя учебного маркетплейса:
- найти программу по названию, автору или категории;
- изучить описание и программу;
- сохранить курс в избранное или добавить его в корзину;
- оформить демонстрационный заказ с выбором способа оплаты;
- получить доступ к урокам после оформления;
- пройти материал, выполнить практическую работу и проверить знания;
- просматривать накопленный прогресс.

## 3. Роли

### Клиент
- регистрируется и входит под личной учётной записью;
- просматривает каталог и карточки курсов;
- управляет избранным и корзиной;
- оформляет демонстрационные заказы;
- проходит доступные уроки и сохраняет прогресс;
- просматривает историю заказов и список купленных курсов.

### Администратор
- входит с ролью ADMIN;
- просматривает каталог, пользователей и заказы;
- добавляет, редактирует и удаляет курсы;
- изменяет демонстрационный статус заказа.

Демо-учётная запись: `admin / admin123`. Пароль используется только для защиты демонстрационного прототипа. Перед публичным или коммерческим использованием учётную запись необходимо заменить, а авторизацию перенести на защищённый сервер.

## 4. Основные сущности

- Пользователь — учётная запись и роль.
- Категория — направление курса.
- Курс — образовательная программа, автор, описание, стоимость и уровень.
- Урок — теоретический материал, пример, практика и контрольный вопрос.
- Избранное — связь пользователя с курсом.
- Корзина — выбранные курсы пользователя.
- Заказ — оформление списка курсов одним пользователем.
- Позиция заказа — курс, количество и цена на момент оформления.
- Прогресс — отметка прохождения урока пользователем.

## 5. Основные сценарии

1. Регистрация → вход → каталог.
2. Поиск → просмотр карточки → избранное/корзина.
3. Корзина → форма оформления → выбор демонстрационного метода оплаты → подтверждение → запись заказа.
4. Купленный курс → программа → урок → тест → сохранение прогресса.
5. Администратор → управление каталогом → изменение статуса заказа.

## 6. Ограничения прототипа

- SQLite — локальная база данных устройства.
- Заказы имеют статус `CREATED_DEMO`; реальные платежи не выполняются.
- Варианты «Карта», «СБП» и «Счёт» показывают только интерфейсный сценарий, не принимают реквизиты.
- Нет облачной синхронизации, удалённого API, видеохостинга и восстановления пароля по email.
- Пароль пользователя хранится в виде PBKDF2-хеша с солью, но для промышленной системы требуются серверная аутентификация, защита сессий и политика управления секретами.
